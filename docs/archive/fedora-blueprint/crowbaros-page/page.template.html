    Built around the work.

    Technical confidence, without making the terminal a prerequisite. The visual edge belongs to the identity; the everyday experience stays welcoming.

    A desktop you can discover
    Mouse and trackpad friendly for everyday users, writers, illustrators, photographers, makers, and Linux tinkerers. Daily life should require no terminal.
    FOSS, with hardware in mind
    The plan commits to a FOSS userland, shell, and default apps, zero telemetry, and the drivers and codecs needed for everyday hardware.
    Start with the essentials
    Browser, files, terminal, settings, and app store. Choose your own creative and productivity tools instead of inheriting a preloaded collection.
    Your tools. Your choice.
    Bazaar starts with Flathub’s floss subset. A clear Settings switch opens full Flathub, with creator donation links built into discovery.
    AI neutrality
    No bundled AI daemons, buttons, or prompts. The hardware foundation leaves room for optional tools users choose to install themselves.
    Open contribution, clear stewardship
    Public RFCs, contributor voting, a founder-steward reserve, and a community gallery anyone can contribute to.

    Observant. Independent.

    A natural, right-facing crow. Folded wing. Slate perch. Precise feather engraving, with one cyan feather connecting the mascot to the mark.

    • Keep the head, beak, and silhouette clear.
    • Use generous scale for the engraved artwork.
    • Use the simple mark for small applications.
    • The mascot is identity artwork, never an assistant.
    Logo spacing & small-size rules

    Clear space: at least one-quarter of the visible symbol height. Horizontal logo: 160 px minimum width. Stacked logo: 140 px. Standard symbol: 24 px and up; micro symbol: 16–23 px.

    Use the outlined masters. Preserve the slash angle, proportions, and orientation. Use the all-Void variant on light grounds.

    Typography, accessibility & voice

    Target 14–17 px UI/body text, 24–42 px headings, and at least 12 px metadata at the reference desktop scale. Honor font scaling, display density, reduced motion, and visible keyboard focus. Retain the optional Atkinson Hyperlegible preset.

    Pair selection color with an outline, label, or state. Ice-filled controls use Void text. Use sentence case and direct language: “Make it yours” and “Find your tools.” Avoid gatekeeping and unsupported security claims.

    Proposed primary address: crowbaros.com. The roles and redirects for .net and .org remain to be decided.

    A little space.
    A different kind of focus.

    Familiar floating windows, clear mouse controls, and optional tiling. Your tools stay within reach, and the desktop steps back when one idea needs your attention.

    Preview appearance

    A desktop you can shape

    Studio Settings brings appearance, widgets, gaps, rounding, fonts, monitor scaling, tablet mapping, shortcuts, and user presets into one graphical home.

    Community Gallery presets and a clear “Reset to Default” keep experimentation reversible.

    Focus, with one gesture

    Super + Z retracts the bar and dock, centers the document, and pauses non-urgent notifications. The writing app in the mockup is optional, not a sixth bundled app.

    Appearance can follow sunrise and sunset. Studio Mode neutralizes chrome while leaving the artwork itself intact.

    Window styling, gestures & Studio color behavior

    Default chrome uses Void and Abyss with Frost text, soft offset shadows, 16 px window/dock radii, 10 px control radii, and a 2 px Ice active-window outline. Spacing follows 4/8/12/16/24/32/48/64 px, adapted to display density.

    Mouse controls must cover move, resize, minimize, restore, maximize, close, and snapping. Tiling and scrolling are optional. Dock, overview, gestures, dialogs, and monitor changes must behave consistently in the selected shell.

    Ice is the official default; wallpaper-derived Matugen accents are optional. Studio Mode overrides tinting with #111111 grounds, #212121 surfaces, #E5E5E5 primary text/selection, and #B8B8B8 secondary text. ICC and Wayland color-management support remain a separate native implementation requirement.

    The greeter follows the selected appearance. Nightwatch leaves a quiet left field for time and sign-in; boot uses the simplified logo and one progress rule. Authentication and encryption prompts must remain legible.

    A composed surface.
    A dependable foundation.

    Fedora’s conventional RPM-based system, a maintained Hyprland fork, Rust foundations, and GPUI interfaces. These are the selected foundations for CrowbarOS.

    Fedora, with conventional packages.

    Fedora 45 is the local build/test baseline, with clean Mock builds, signed development RPMs, and DNF installation tests. Production hosting/signing, the installer, support lifetime, and recovery remain to be finalized.

    FedoraRPMDNF

    Hardware we can support

    Validate AMD, Intel, and NVIDIA configurations, including hybrid laptops, display docking, suspend, and creative peripherals. Publish the tested support matrix.

    Drivers, codecs & hardware packages

    Firmware, Mesa, hardware video acceleration, media codecs, printing, and tablet support belong in the Fedora package plan. Validate NVIDIA driver and kernel combinations separately.

    Resolve package sources, module signing, and installer detection for the supported Fedora release. The previous Universal Blue image streams are superseded.

    Updates with a release owner

    Build and test compatible compositor, library, portal, shell, and plugin versions together. Promote development builds through testing before stable delivery.

    Provide graphical RPM/DNF updates through Rust/GPUI, preserve user settings, and prove recovery on Fedora. Backport relevant security and critical fixes while feature upgrades complete integration testing.

    A maintained fork, with a small difference

    crowbaros-hyprland tracks upstream stable releases. Keep compositor patches focused, with an owner, purpose, regression check, upstream reference, and removal condition. Branding and application logic stay outside the compositor.

    Integrate each selected upstream release on a test branch. Publish separate CrowbarOS release tags and an exact version manifest; preserve upstream tags and published history. Contribute generally useful fixes upstream when appropriate.

    Release checks cover mouse-only window controls, dialogs, dock and overview state, hardware, sharing, accessibility, and upgrades with existing user settings. The repository and pipeline are planned, not yet implemented.

    Rust foundations. GPUI interfaces.

    Use Rust for new CrowbarOS-owned native apps, services, helpers, and shared models. Existing upstream projects keep their languages, including Hyprland C++ and necessary patches.

    GPUI is the selected toolkit for our application and shell interfaces. Share controls, design tokens, and accessibility behavior across Studio Settings, onboarding, desktop controls, and the greeter. Pin GPUI and test upgrades with the desktop release.

    Keep application logic behind typed Rust service interfaces. Validate text input, accessibility, scaling, dialogs, drag-and-drop, motion, and power use. Implement and test Wayland panel, dock, and secure locking integration separately from ordinary GPUI app windows.

    Your settings stay yours.

    Packaged system defaults/usr/share/crowbaros/defaults/
    User overrides · yours to keep~/.config/crowbaros/user/

    Rust settings services own a versioned, readable override schema and generate backend configuration through adapters. Export a .preset; test migrations and retain a recoverable copy of prior settings.

    Preserve Hyprland’s BSD-3-Clause and GPUI’s Apache-2.0 notices. CrowbarOS-owned components follow the planned GPL-3.0 / MPL-2.0 direction; audit the complete dependency manifest when packaging.

    Open contribution.
    Explicit responsibility.

    A public, multi-class voting ledger gives contributors a defined voice, with a founder-steward reserve to anchor the vision and resolve exceptional cases.

    A reserve, with a stated norm.

    For standard proposals, classes B–E vote first. At least 33 of 49 contributor votes, together with respect for the core charter, leads to founder ratification by default.

    The 51% reserve is for deadlocks, security emergencies, or protecting the founding vision. It is part of the model, openly stated.

    The charter protects FOSS userland, the lean core, AI neutrality, and the CrowbarOS design system.

    1. Public RFCSeven days of comment
    2. Class votePublic contributor ledger
    3. RatificationApply the reserve-veto norm
    4. Recorded decisionPublish outcome & rationale
    Membership, elections & the open gallery

    Membership in classes B, C, and D is earned through sustained contribution—for example, five non-trivial merged PRs or maintained modules over six months—and reviewed semi-annually. Community members elect class E annually.

    Anyone can publish a supported shell widget, workflow preset, or theme to the Community Gallery through automated CI lint and security checks. The Rust/GPUI shell’s extension API remains to be defined and versioned. Gallery contributions need no founder permission or governance vote.

    From foundation
    to a live desktop.

    A provisional sixteen-week sequence in two stages. Re-estimate after Fedora packaging, GPUI shell integration, and fork-maintenance prototypes. Release checks take precedence over the calendar.

    Desktop Alpha

    Weeks 1–8
    1–2Bootstrap & pipelineIntegrate Fedora, the fork, and GPUI.

    Use the Fedora 45 build/test VM lab, record dependency versions, establish the Hyprland upstream baseline and patch ledger, and set Rust workspace conventions. Pin GPUI, build a settings slice and Wayland panel prototype, and validate signed RPM installation and checkpoint restoration. Physical hardware testing follows later.

    3–5Shell & ergonomicsMake floating windows and focus feel natural.

    Build Rust/GPUI shell controls and Hyprland adapters. Prove mouse-only floating-window controls, minimize/restore, snapping, dialogs, dock, overview, and monitor changes. Build Zen Mode with reliable restoration and complete one upstream integration cycle with the pinned desktop stack.

    6–8Identity & the lean coreBring the brand into the native desktop.

    Build default Dark, Light, Warm Paper and neutral Studio modes. Integrate the exact palette, fonts, logos, and crow/feather artwork across shell, boot, lock and greeter. Verify contrast, scaling and reduced motion. Wire up protected defaults and user overrides; preload only the five core apps.

    Hardware polish & live ISO

    Weeks 9–16
    9–11Hardware & Studio SettingsMake the important hardware controls graphical.

    Add multi-monitor fractional scaling, Wacom pressure and screen mapping, shortcut remapping, and the transparent full-Flathub switch to Studio Settings.

    12–14A live-testable installerTry the desktop from USB before installing.

    Integrate a graphical installer for the Fedora RPM-based system. Let users test Wi-Fi, GPU, and trackpad behavior in a live Hyprland + Rust/GPUI session before installing with LUKS2 encryption. Validate DNF-based updates and recovery on the supported hardware matrix.

    15–16Charter, community & v1.0Meet the release checks and publish support scope.

    Publish the charter, design guidance, fork-maintenance policy, support scope, and known issues. Curate optional Bazaar shelves and open the Community Gallery. Release v1.0 after desktop, accessibility, hardware, and upgrade/recovery checks pass.

    Six repositories, with clear boundaries
    crowbaros-os
    Fedora RPM specs and repository definitions, hardware integration, installer, release manifests, signed builds, and upgrade/recovery tests. Apache-2.0 / MIT build recipes.
    crowbaros-hyprland
    Maintained compositor fork, upstream tracking, focused patches, integration branches, and tested releases. Preserve BSD-3-Clause notices.
    crowbaros-shell
    Rust apps, services, shared models, GPUI components, and Wayland/Hyprland adapters. Pin GPUI and retain its Apache-2.0 notices alongside the planned GPL-3.0 project license.
    crowbaros-themes
    Dark, Light, Warm Paper, neutral Studio tokens, artwork, fonts and Matugen templates. Planned MPL-2.0 / CC-BY-SA distribution, with separate font OFL notices.
    crowbaros-gallery
    An open registry: JSON index and CI validation for community presets, themes and plugins.
    crowbaros-rfcs
    Charter, governance, design-system HIG, public proposals and vote tallies. CC0 / public record.

    GitHub is the primary home, with an automated Codeberg mirror. Repository names describe the planned structure.
