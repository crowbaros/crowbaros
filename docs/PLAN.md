# Fulcrum

## A production Wayland compositor for CrowbarOS

Build Fulcrum as a separately released Rust compositor on Smithay. Its first customer is the CrowbarOS Base image. A successful release lets a person boot CrowbarOS, launch and arrange applications, use multiple displays, move data deliberately between apps, and lock and recover the session. The existing GPUI shell supplies the bar, dock, launcher, and Settings UI. Fulcrum owns the pixels and input decisions those components must be able to trust.

**Start by extracting the existing production compositor.** The CrowbarOS checkout at `30fadd8` already has a Rust 2024 workspace, a pinned Smithay revision, real Wayland client tests, a development-only nested backend, and a Void TTY backend. The first of its six planned slices implements connection identity, protocol visibility, and redraw on change. Separately, the Alpha desktop runs a research spike. Its recorded 37-check desktop run gives Fulcrum a concrete replacement target. Those are two different baselines. [Production workspace](https://github.com/crowbaros/crowbaros/tree/30fadd8e88fbeb9991eb340f5dee27998b02c9fe/compositor) · [Alpha desktop evidence](https://github.com/crowbaros/crowbaros/blob/30fadd8e88fbeb9991eb340f5dee27998b02c9fe/docs/development/void-desktop-smoke-2026-11-15.md)

## What to adopt from Smithay compositors

Use other compositors as design references. Implement the selected behavior in Fulcrum under CrowbarOS's MIT policy and retain the existing Smithay notices. The selection criterion is whether an idea improves the CrowbarOS session and can be verified in its lab. [Smithay's list of compositors](https://github.com/Smithay/smithay#other-compositors-that-use-smithay)

| Reference | What to take | Where it pays off |
| --- | --- | --- |
| [COSMIC](https://github.com/pop-os/cosmic-epoch#components-of-cosmic-desktop) | A compositor, shell components, settings, and session services can each have a clear owner while shipping one integrated desktop. | Keep the GPUI shell independently restartable. Have Settings request output changes through the shell's versioned interface. Verify both against the same Fulcrum release. |
| [niri](https://github.com/niri-wm/niri#about) | Monitor disconnect and reconnect have deliberate window-placement behavior. Its development work also uses randomized layout testing and measures input latency. | Test unplugging a monitor during a move, changing scale, and reconnecting. Check that every window is reachable and keyboard focus remains valid. Use its scrolling columns as a post-Beta layout candidate. |
| [Pinnacle](https://github.com/pinnacle-comp/pinnacle#features) | Layout can be a distinct policy with floating and tiling behaviors. | Give the Rust window model a testable layout function. Start with floating and half-screen snap. A later tiling experiment can use the same windows, focus rules, and trusted frames. Keep executable configuration outside the trusted compositor. |
| [Otto](https://github.com/nongio/otto#what-you-get) | A stacking desktop can make placement, snapping, and switching feel like one interaction. | Use opening two windows, snapping them side by side, opening a dialog, and switching back by keyboard as a usability test. Keep CrowbarOS's existing workspace and frame conventions. |
| [Smithay Anvil and Smallvil](https://github.com/Smithay/smithay/tree/master/anvil) | Upstream reference implementations for backend and protocol changes. | When a Smithay update changes DRM or input behavior, compare the pinned examples with Fulcrum. The existing backend already draws on Anvil and the handlers on Smallvil. |

## Project ownership

| Owner | Responsibilities |
| --- | --- |
| **Fulcrum** | The `crowbar-compositor` binary, Wayland connections and protocol policy, window and output state, input routing, rendering, trusted frames, lock state, private protocol definitions, the probe client, and compositor tests. Keep the existing binary name through extraction so service changes can be tested independently. |
| **CrowbarOS** | The GPUI shell and Settings, the Warden that starts compartments, the broker that records authority and data transfers, runit services, the Void build, hardware lab, and the decision to roll a Fulcrum version into Base. |
| **Smithay** | Wayland and Linux graphics primitives. Carry the existing Smithay and DRM-extras pin together. Follow the agreed monthly update cadence, with a dedicated change and the existing guest and NVIDIA checks. [Dependency policy](https://github.com/crowbaros/crowbaros/blob/30fadd8e88fbeb9991eb340f5dee27998b02c9fe/docs/adr/0020-the-first-compositor-is-small-on-purpose.md#the-smithay-pin) |

Keep one compositor process. Give its event loop ownership of seats, outputs, windows, and pending confirmations. Keep decisions such as focus transitions and window geometry testable with plain Rust data. Both backends should exercise the same input, policy, and window code. Build the test probe as a separate executable. Add crates only when a second consumer needs an independently versioned interface.

The OS integration contract has three parts. The shell and Warden have separate identity-checked connections. Each application inherits its identity from the Wayland listener registered for its compartment. The shell and broker control channels use versioned, length-prefixed messages with explicit request IDs. For each release, publish the supported protocol version alongside the source revision. A change to what a client can see, draw, or confirm needs a matching decision and behavioral test on the consuming side. [Client identity](https://github.com/crowbaros/crowbaros/blob/30fadd8e88fbeb9991eb340f5dee27998b02c9fe/docs/adr/0016-the-warden-starts-every-compartment.md) · [Control protocol](https://github.com/crowbaros/crowbaros/blob/30fadd8e88fbeb9991eb340f5dee27998b02c9fe/docs/adr/0018-one-gesture-answers-one-ask.md)

## Implementation milestones

| Milestone | Deliverable | Exit check |
| --- | --- | --- |
| **0 · Independent build** | Extract the production workspace with relevant Git history, lockfile, licenses, checks, and probe. Make Fulcrum the source of compositor changes. Teach the CrowbarOS Void builder to consume a pinned Fulcrum revision in its offline build. Cross-link existing issues so each item has one owner. | From fresh checkouts, build and test with the lockfile, run the existing nested check and the Void guest compositor check, and record both repository SHAs. Demonstrate that reverting the consumer pin restores the previous build. |
| **1 · Trusted shell session** | Implement slice 2, issue 71. Connect the shell and broker, identify the displayed ask, arm it after it is visible, focused, topmost, and steady for one second, and bind the physical confirm chord to that ask. Handle shell reconnect. Plain answers follow the separate shell path in ADR 0026. | Show one deliberate confirmation for one ask. Change its contents or restart the shell before the chord and verify the previous ask cannot be confirmed. Repeat with the actual GPUI shell. Use a broker stand-in while its service is being built. |
| **2 · Working window manager** | Implement slice 3, issue 78. Deliver trusted frames and stacking, click and keyboard focus, move, resize, maximize, fullscreen, half-screen snap, and nine workspaces shared across displays. | Launch two real apps from the shell, arrange them by mouse and keyboard, open a child dialog, switch workspaces, and return. Focus follows the person's action. A fullscreen app retains its trusted frame. |
| **3 · Clipboard and capture** | Implement slice 4, issue 166. Handle clipboard, primary selection, and drag and drop. Associate each cross-compartment transfer with the person's action and report it to the broker. Support shell-owned screenshots and previews. | Exercise keyboard paste, middle-click, menu paste, and drop in real clients. A focus change alone transfers nothing. Check the broker's source, destination, and action for each transfer. Verify shell-only capture. |
| **4 · Displays, input, and frame delivery** | Implement slice 5, issue 79. Persist output mode, position, and per-display scale. Handle hotplug, seat devices, suspend/resume, and explicit sync. Hardware work can begin alongside shell and window work. | Collect results on the software-rendered Void guest, RTX 4090, Intel iGPU, and Surface ARM compositor target. On applicable hardware, verify mixed scale, display removal, GPUI frames after resume, and zero redraws on a still desktop. Record missed presentation deadlines against the actual output refresh period. |
| **5 · Lock and recovery** | Implement slice 6, issue 87. Start locked, route input exclusively to the lock surface, blank secondary displays, and let the broker authorize unlock. Integrate idle, suspend, and service restart. | Restart the shell during an ask, restart the compositor during a session, and suspend with a second monitor attached. Each recovery reaches its documented state before an app receives input or becomes visible. Test the real broker for release qualification. |
| **6 · CrowbarOS cutover** | Pin a Fulcrum release candidate in Base. Update Alpha's service invocation and launch wiring to the production interfaces. Replace the spike after the production compositor passes the full desktop check. | Run the existing desktop smoke scenarios, including launch, Settings Save/Undo, persistence after restart, and service isolation. Verify that the actual Warden and broker satisfy the contracts exercised by stand-ins. Boot the previous Base generation to prove rollback. Publish compatibility and hardware results with the release. |

The OS already has decisions and issues for slices 2–6. Preserve their order and revisit ask, paste, and unlock behavior as Milestone 2 produces evidence. Before cutover, also close the open resource-accounting gap or document its disposition with the OS owners. The current production workspace records that one compartment can consume the descriptors needed to serve other clients. ## After the first release

1. **Everyday access.** Work with the shell team on trusted input methods and cross-app screen-reader support. Qualify each with a user completing a real task across two compartments.
2. **Window sharing.** Implement a broker-mediated picker for a single window. Use a real call to verify target selection, resize, closing the shared window, and revocation.
3. **Optional layouts.** Prototype niri-style scrolling columns and Pinnacle-style dynamic tiling against the same window model. Compare them on a three-app workflow, a transient dialog, keyboard navigation, monitor removal, and a trusted confirmation. Ship the mode that earns its complexity.
4. **Hardware expansion.** Add AMD and hybrid-GPU rows as machines become available for recurring qualification. Treat high-refresh frame pacing, VRR, and color management as separate features with measurable acceptance tests.

**First implementation PR:** import the production subtree at a recorded revision and reproduce its headless tests in Fulcrum. **First paired CrowbarOS PR:** run the Void compositor check against that exact external revision. Together these prove the repository split before any behavior changes, and give the shell team a reproducible build to target for issue 71.
