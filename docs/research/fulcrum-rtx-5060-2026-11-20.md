# Base and Fulcrum on an RTX 5060

**Result (November 20, 2026): Base's image boots real hardware and runs the
desktop on an RTX 5060 with NVIDIA's driver.** Fulcrum drew with
`renderer=gles` on the GPU, put the pointer on the cursor plane, drew a GPU
client's buffers, and offered explicit sync, which NVIDIA's Vulkan used. The
desktop flow passed by hand, with one bug in the launcher. One row that must
pass failed: a still desktop keeps drawing
([#269](https://github.com/crowbaros/crowbaros/issues/269)), in the VM as well
as here. Suspend first woke to a grey screen, and a driver option fixed that
on the same machine.

This is the record that
[issue 227](https://github.com/crowbaros/crowbaros/issues/227) asks for, run
by hand with [Base's hardware guide](../../base/HARDWARE.md). Jim Martin was
at the machine for the rows done by hand. A coding agent drove the rest over
SSH and read the logs. The evidence is in
[`evidence/fulcrum-rtx-5060-2026-11-20/`](evidence/fulcrum-rtx-5060-2026-11-20/).
The earlier [NVIDIA record](compositor-nvidia-2026-11-15.md) was made with the
Smithay-based spike, and says nothing about Fulcrum.

## Found by hand

- **Super opens the launcher without the keyboard.** Typing went nowhere until
  Jim clicked the search field. Fulcrum gives a layer the keyboard only on a
  click, and ignores the launcher's `exclusive` keyboard interactivity. The
  desktop check never types into the launcher, so it missed this.
  [#270](https://github.com/crowbaros/crowbaros/issues/270)
- **The bar is about a second late with a workspace change**, by
  Super+number or by moving a window to another workspace.
  [#273](https://github.com/crowbaros/crowbaros/issues/273)

## Suspend and resume

Both suspends went through `zzz`, into `deep` sleep for about 18 seconds, and
were woken from the machine. Base's hook locked the session first, and Void's
`nvidia` package's hooks ran `nvidia-sleep.sh`.

The first time, the driver ran with its defaults,
`PreserveVideoMemoryAllocations: 2` and `TemporaryFilePath: ""`. On resume:

```text
NVRM: Xid (PCI:0000:01:00): 13, Graphics Exception: Shader Program Header 18 Error
NVRM: Xid (PCI:0000:01:00): 13, pid=792, name=crowbar-composi, Graphics Exception: channel 0x00000002, Class 0000ce97, Offset 00000000, Data 00000000
```

Fulcrum kept running and counting frames, but drew grey.

For the second time, one file was added to the SSD's root by hand,
`/etc/modprobe.d/nvidia-suspend-test.conf`:

```text
options nvidia NVreg_PreserveVideoMemoryAllocations=1 NVreg_TemporaryFilePath=/var/tmp
```

After a reboot, the driver reported `PreserveVideoMemoryAllocations: 1` and
`TemporaryFilePath: "/var/tmp"`. The second suspend logged no Xid, woke to the
lock screen, and unlocked to a working desktop with `foot` taking keys. The
image does not carry that file yet; #272 is to add it.

## Not run

- Only one monitor was plugged in, so no second output, and no panel dense
  enough to need a scale other than the one Fulcrum chose.
- Wi-Fi: the machine was on wired Ethernet. Base has no Wi-Fi firmware for its
  card yet ([#217](https://github.com/crowbaros/crowbaros/issues/217)).
