CrowbarOS · a counter-proposal from Jim

Don't ship a desktop.
Ship the ability to make one.

Jason, your CrowbarOS blueprint is a beautiful, curated desktop. I want to pitch a bolder bet on the same name and spirit: an agent-first OS that starts almost empty, where every person speaks their ideal OS into existence.

The shift I'm seeing

People are increasingly building bespoke software instead of installing existing software. Today that's mostly experienced developers working with agents. But the cost of making a small, perfectly-fitted tool is collapsing, and I think within a few years everyone will do it.

If software becomes something you describe instead of something you install, the OS's job changes.

A curated set of five default apps matters less when your file manager or writing app might be something your agent built for you last Tuesday. What matters is the substrate: a tiny, stable base, an agent that can build and change things safely, and a way to keep, undo, and share what you make.

What it feels like

you › I write in the mornings. Give me a calm writing mode with no notifications until noon.
agent · built "Morning Pages" app, added a focus rule 6am–12pm, warmed the palette
agent · new system generation #42 saved, one click to undo
you › Nice. Make the dock disappear unless I push the mouse to the bottom.
agent · done, generation #43

No app store browsing, no settings archaeology, no terminal required. And because every change is a saved version, nothing the agent does is scary.

Five first principles

01

Everything is declared and versioned

The whole system is a living document the agent edits, with full history and instant rollback built in, not bolted on.

02

Capabilities, not root

Every generated app gets only what it was granted: this folder, the camera, the network. A buggy bespoke app can't wreck the machine.

03

Intent is a first-class interface

The agent is a system service with a stable API to the whole OS, not a chatbot app sitting on top.

04

Apps are generated and disposable

The OS is optimized for building, sandboxing, testing, and swapping small programs constantly, not installing big ones.

05

Your OS is portable and shareable

Your entire setup is a definition you carry to a new machine, or share so a friend can try your OS in one step.

The stack: bold where it's new, borrowed where it isn't

I'm open to going all the way down to the metal where the vision demands a new way of thinking. But nothing about agent-first needs a new way to talk to a Wi-Fi chip, and drivers are what kill new OSes. So invent the top, borrow the bottom, and keep the kernel swappable.

Practical starting point: a minimal NixOS-style declarative base (the agent edits config, every rebuild is a rollback-able generation) with Hyprland, plus our own capability layer on top. Longer term, a capability microkernel like seL4 could replace Linux under the same design.

The hard problems (where I want your brain)

  1. Trust. What can the agent change without asking, and how does a non-developer stay in control?
  2. Where the model runs. Local, cloud, or the user's choice, and what's the floor for hardware?
  3. Recovery. When someone's bespoke stuff breaks, how do they get back to good without knowing what a config file is?
  4. Sharing and community. Does the Community Gallery become a place to share prompts, apps, and whole OS definitions?
  5. Does this kill your AI-neutrality pillar, or can both coexist, for example an agent-first edition alongside a classic one?
